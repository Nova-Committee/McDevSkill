# 选择验证与记录证据

先读 `mc-discipline`。

## 证据分层

| 证据 | 能证明 |
| --- | --- |
| 构建、单元测试 | 当前工具链产生了产物，已运行断言的逻辑符合预期 |
| GameTest | 引擎与夹具实际触发的注册、服务端状态或行为 |
| 专服就绪、客户端主菜单 | 各自已执行到启动检查点 |
| 真实客户端输入、画面、服务端回读 | 分别证明输入落地、当帧显示、权威数据变化 |
| 保存后结束进程并重开同档 | 持久化、重绑定和冷启动可恢复 |
| 实际加载器发现技能、独立消费者读取导出 | 使用方能够发现或消费当前交付物 |

仅测试能回答本次风险的路径。注册或数据使用实际加载包和消费者。文档与技能查实际发现和引用。`NO-SOURCE`、跳过、启动失败和缺少目标环境分别记录。

## 双端与图形会话

- 客户端症状使用真实图形双客户端，分别经过可用的实际服务端路径并验证触发者与第二身份的观察。单机专属入口如无法组成双端，写清实际验证条件。服务端夹具可以补覆盖权限和落盘，原生焦点、输入、裁剪和图层需真实界面验证。
- 在同一连续图形会话内完成启动、绑定目标、实际操作、截图和退出。会话中断后重新建立并核实上下文，复跑受影响的对照。记录实际窗口尺寸、GUI 缩放、光照、动作、原始截图和对应产物哈希。
- 版本错配、软件渲染代替目标硬件或替代夹具，都在报告、证据和交接中永久标明。单独报告替代环境中的观察，目标条件保持未验证。专属硬件性能、输入法和音频各取对应实证。

## 永久测试

复用现有夹具，保留能捕获真实回归的边界、守恒、状态转换或失败副作用断言。纯逻辑用最小运行环境，依赖引擎注册时用当前项目的实际入口。源码字符串、非空、简单转发和重复实现当预期都不能代替行为。出现夹具缺陷先修夹具。

## 收尾回执

记录本轮实际启动的进程身份、工作目录和监听端口。验证后正常退出客户端、专服及图形和控制会话。逐项回查进程、端口和断开后可能残留的子进程。只处置确认归本轮且有权限的进程，报告仍在运行的身份和阻塞。附读回时间、命令和清理结果。
