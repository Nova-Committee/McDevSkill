# 界面加载、布局与输入

## 找到实际消费的模板与槽位

- **适用条件** 当你修改界面模板、额外开窗参数或可见槽位时。
- **观察到的现象** 你可能看到换了 JAR 仍是旧布局，或者格子隐藏后仍能接收点击和物品移动。
- **判断依据** 你要查模板何时从资源写到运行目录、何时读取运行副本，并区分服务端开窗参数、容器槽索引和客户端可见格子。
- **做法** 你可以用真实开窗动作验证参数到达，在隔离实例检查现有副本、首次生成和重载。对照菜单映射实际点击、快速移动与服务端读回。
- **反例/坑** 你若直接覆盖运行副本，可能抹掉用户定制。可见性开关对槽注册的影响取决于界面框架和版本，需要从当前实现确认。

## 刷新后重绑挂载节点并按有效几何命中

- **适用条件** 当你维护可刷新的文档界面、HUD、工具栏或临时相机时。
- **观察到的现象** 你可能看到刷新后节点还画着，却失去样式或点击；也可能看到 HUD 被裁剪、透明区域挡住世界操作。
- **判断依据** 你要核对当前挂载的根节点、刷新代次、渲染与命中矩形。绝对定位子节点是否撑开祖先，要按框架现有的布局契约确认。
- **做法** 你可以把草稿和选择放在节点生命周期之外。根节点更换时重新绑定样式作用域和监听。用同一逻辑几何判工具栏，再对世界区执行射线判断；退出时归还实际接管的相机与按键。
- **反例/坑** 你若继续持有旧根节点的引用，刷新回调会写到已卸载界面。透明背景也不代表输入会自动穿透。

## 用实际窗口验证提示和短暂反馈

- **适用条件** 当你需要在紧凑界面展示坐标、状态或服务端拒绝原因时。
- **观察到的现象** 你可能看到正常窗口能读全，窄窗里数值断开、悬浮提示压住相邻控件，或移开鼠标就看不到拒绝原因。
- **判断依据** 你要比较实际 GUI 逻辑宽度、本地化后文本测量、提示锚点，以及相邻控件的绘制和命中区域。
- **做法** 你可以在有语义的分隔位置允许折行，将拒绝原因放在界面上的短暂反馈区域。用宽窄窗口、实际语言和真实点击核对提示、移开鼠标后的可见性及相邻控件可操作性。
- **反例/坑** 你若按截图像素设固定折行点，缩放或翻译变化后可能裁掉数值。只把原因放进 tooltip 会让失败反馈依赖鼠标驻留。
