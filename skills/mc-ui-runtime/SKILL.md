# 原生界面与输入

先读 `mc-discipline`。

## 实际加载入口

- 从游戏交互追到服务端开窗或报价、菜单数据、实际屏幕、活跃模板或文档、布局与绘制。对比真源、成品、运行复制件及重载行为。已有模板可能是用户成果，保留后再按本次范围处理。
- 区分机器槽、容器槽、可见格子和真实点击索引。实际读回当前菜单映射。用给出的真实坐标和数据打开菜单，布局图不能替代槽位注册或权威移动结果。

## 布局与生命周期

- 使用实际图形窗口、GUI 逻辑尺寸、缩放和语言复现。绘制、范围和命中共用几何。窄窗优先保留操作锚点、完整内容和局部滚动。短暂拒绝应可在移开鼠标后读取，提示框不要覆盖仍需操作的控件。
- 草稿、选择与滚动独立于节点。刷新后重绑实际挂载的节点和监听；迟到回调检查当前屏幕、文档和上下文。HUD 优先查祖先可用尺寸以及裁剪链，保持一个实际拥有者。

## 焦点、弹层与世界输入

- 核对焦点、字符输入、取消传播、透明区域、弹层顺序及释放手势。文本框消费自己的键，对话框只关闭当前一层。工具栏命中和世界射线各用正确的坐标空间；世界区可以交互且工具栏不穿透。
- 相机等临时输入拥有者要能在退出、换世界和异常时释放。画面提示表示客户端状态，业务授权和迟到回执见 `mc-server-state`。第三方界面共存注册见 `mc-port-and-integration`。

验证受影响的实际入口、焦点和相关尺寸，覆盖一次重开或刷新。图形会话和截图的证据要求见 `mc-verify-change`。
