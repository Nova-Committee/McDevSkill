# 通过 MCP 操作真实客户端

先读 `mc-discipline`。根据 `mc-verify-change` 选择本轮需要的证据。你可以使用已有 MCP 驱动的客户端，接口名称与能力以当前环境为准。随附封装已验证可连接 Calcite 的 MCP，作为可选实现。安装和连接方式见 [McTestHarness 说明](harness/README.md)。

1. **启动与绑定**。在同一控制会话启动隔离客户端，核对实际 Minecraft 版本、加载器、依赖、包的哈希和专用服。确认要操作的客户端已经进入预期世界或界面。需要独立账户运行时，由环境维护者在外层用 `runuser` 或 `sudo` 配置。
2. **观察**。读取当前状态、周边方块和实体、手持物及容器内容。通过当前画面或服务端事件确认操作对象和触发条件。
3. **操作**。沿玩家真实入口走动、挖掘、交互或点击槽位。每次核对界面和服务器响应，避免把已派发的输入当作已完成的动作。
4. **取证**。在当前绑定的客户端保留画面和日志，并取相应的服务端回读。记录版本、窗口、缩放和证据所对应的操作。替代环境单独标注。
5. **退出并回读**。用驱动停止本轮客户端，退出控制会话，并按归属检查专服、窗口服务、监听端口和子进程。给出清理回执。

在随附的封装中，微软登录和已有微软账户入口被禁止，避免凭据或登录挑战进入模型上下文。单机世界入口被禁止，验证在隔离的测试服务环境中进行。渲染必须保持可用，图形验收需要实际截图。工具白名单写在代码中，且同样约束直接发来的 MCP 调用。
