# 真实客户端的会话与取证

## 在同一个控制会话完成取证

- **适用条件** 当你通过控制驱动启动客户端并采集真实游戏画面时。
- **观察到的现象** 你可能看到新连接里仍有相同的客户端名称，实际世界、焦点或进度已经不同。
- **判断依据** 你需要用同一会话的客户端绑定、位置、界面状态与响应核对操作和截图对应的对象。
- **做法** 你可以在一条连续会话中完成启动、操作与截图。断开后重新绑定并核实现状，再复跑受影响的步骤。
- **反例/坑** 你若只按名字复用上次的状态，可能把另一个进程的截图归给当前操作。

## 分别记录目标与替代环境

- **适用条件** 当你只能用错配版本、软件渲染或替代夹具复现部分操作时。
- **观察到的现象** 你可能看到替代组合能进服、操作和截图，目标组合仍在启动或图形阶段失败。
- **判断依据** 你要核对专服与客户端的实际版本、渲染实现、已验证动作和目标环境失败的位置。
- **做法** 你可以在原始证据、验收报告和交接中一直保留替代标记，分别列出替代组合已观察到的结果与目标组合的未验证项。
- **反例/坑** 你若把替代版本的通图等同于目标通过，后面就无法区分功能结论与环境阻塞。

## 按会话归属清理并回读

- **适用条件** 当你同时运行多个隔离客户端、专服或控制会话时。
- **观察到的现象** 你可能看到结束一个客户端后，关联的游戏、控制子进程或监听端口仍在。
- **判断依据** 你要用本轮的进程身份、工作目录和端口确认归属，分别核实已退出和仍需收尾的对象。
- **做法** 你可以先通过驱动正常退出客户端和会话，再独立回读本轮进程与端口。记录检查命令、可见结果与仍在运行的对象。
- **反例/坑** 你若按名称批量终止，会打断其他任务。只读一个端口也无法证明它关联的进程已经退出。
