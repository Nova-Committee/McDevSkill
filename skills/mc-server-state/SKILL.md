# 服务端权威状态与生命周期

先读 `mc-discipline`。

## 所有者、提交与回执

- 区分注册类型、完整逻辑 ID、实例 UUID、玩家与空间、外观和界面选择。服务端从实际操作者、目标、来源、维度、权限与存活状态校验写请求。开窗、报价、预览、刷新和关闭不结算资源。
- 在扣物、记账、奖励、工程登记或保存前完成可失败的前置检查。按真实对象与组件核对来源和守恒。冻结已承诺业务所用的数据，读取和重载不重复扣费或补货。
- 迟到回执关联原请求和上下文。等待时防重复，拒绝保留权威原因，关闭界面与服务端撤销分别处理。临时会话在正常退出、断线、死亡、换世界、权限失效等实际入口释放，只撤销本功能授予的能力。

## 全局状态与个人出生点

- 先分清全服重生点、玩家个人床或重生锚、维度默认落点、所有者设置和访客回程。沿目标 API 的实现追到最终持久化字段和同步范围，确认看似属于某个世界的 setter 是否实际委托给全服对象。
- 私人传送只写自己的权威记录。创建时先计算并赋值完整设置，再登记并标脏。保存自选点时由服务端读取实际位置，检查目标维度和站位安全。失败回退按约定验证，保留应保留的自选与回程记录。
- 用两身份对照。A 建界或保存后查全服状态与通知，B 从未设置个人重生点时实际死亡重生，再独立验证已有个人重生点。复核所有者、访客与两个个人世界的落点和回程是否隔离。改到持久化时冷启动同一份隔离存档并回读。

## 实体冷加载与维度退出

实体未加载与数据不存在分别处理。恢复前确认区块、实体和注册生命周期，不能从瞬时空查询推断可重建。删除隔离维度先疏散玩家，再卸载并处理注册和磁盘数据，按实际实现核对顺序。公共通信与专服类加载边界见 `mc-port-and-integration`。
