# 数据、协议与内容演进

先读 `mc-discipline`。

## 真源与消费者

- 沿规范数据、生成器、来源目录、实际构建产物、加载器、业务消费者和持久化追踪。字段变化同步编码、校验、示例、生成资源与文档。完整命名空间 ID 用于引用，显示名保留给界面。
- 删除已确认关联的注册、配方、标签、掉落、动态 ID、网络、界面与翻译、脚本和存档引用。验证剩余玩法与不变量，源码扫描只辅助定位。

## 数据包、脚本与重载

- 对每一类定义独立核实加载来源、优先级、同源顺序、同 ID 覆盖、删除定义与移除派生配方的区别。以当前实现和最终生效条目为准，普通配方与自定义定义可能采用不同规则。
- 验证目标版本的真实数据包或脚本引擎。分别记录启动后与 `/reload` 完成后的读回，判断是否需要重新发包、刷新界面或重启。看最终消费者的查询、解锁或产出，也核对未知 ID、无效字段和冲突结果。
- 复用目标仓库已维护的编写指南与实际范例，检查分支适用性。保留指南链接，字段和示例在项目内维护一份。

## 迁移与网络

- 先明确需要保留的真实旧格式与拒绝边界。用实际旧样本、独立预期、重复读取及无关字段保留验证迁移。有意断代就在写盘前拒绝并给出原因。
- 协议需要确认两端消费语义、字段顺序和识别能力。类型未变也可能破坏兼容。需要新旧端共存时保留旧路径的实际契约，按目标加载器协商，并实测两种连接方向。

## 草稿、检查与发布

预览、私有草稿、针对当前修订的检查、获准发布是不同动作。过期诊断不能批准发布，失败应保留上一份有效发布。已承诺的交易、任务和施工消费冻结输入，热重载只影响该规则允许更新的对象。
