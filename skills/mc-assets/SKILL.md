# 资产来源与运行时渲染

先读 `mc-discipline`。

## 来源与实际绘制

- 记录授权、可编辑真源、生成参数、导出件、运行模型或图集与实际消费者。画面错误优先找到加载的副本和生产阶段，修复落到可维护真源。
- 区分像素图与平滑图的采样、透明度和边缘处理。只改受影响的纹理或渲染状态；图集和模型缓存随相应资源重载失效。检查 UV、法线、骨骼变换、接触点、模型姿态和业务触发的对应关系。
- 结构旋转同步几何、方块方向和功能锚点，第三方方块实体数据按真实契约处理。预览实体不进入正式世界，共享模型和渲染状态需恢复。

## 亮度、着色与遮挡的量化

1. 先定义实际参照和验收差值。比较 GUI 图标亮度或着色时，采集同一个物品对应的放置态，在固定光照下取相同表面；没有放置态时用有相同语义的独立参照并注明。测遮挡时保留同屏邻格或同场景的空槽控制帧。
2. 固定视角、光照、窗口、缩放和资源包。保留未经修改的原始帧，注明采样区域、像素颜色或亮度算法、噪声阈值与单位。动态效果取若干可复核帧，报告可重复区间。
3. 一次只改一个变量。用一致的取样比较区域亮度差、最大或平均变化、越过边界的距离和像素数量。验收同时看与放置态差距是否达标，或是否保留本格效果而邻格低于阈值。具体数值按需求、参照和控制帧确定。
4. 从几何范围、混合模式、深度测试与写入、图层提交顺序、着色或裁剪分别解释。验证实际运行的渲染状态。若资源或 shader 条件变化，给出该结果适用的版本和组合。
