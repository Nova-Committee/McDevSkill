# Minecraft 开发纪律

## 开工与范围

- 先核实用户确认的范围、目标工作树与基线、项目规则、游戏版本、加载器、工具链和依赖。环境与启动入口从当前项目或当前能力清单取得。旧环境、旧产物和旧验收只作线索。
- 写清正常入口、实际消费者、预期结果和风险。跨存档、协议、第三方集成或多个责任域时先确认边界，再用一份任务清单跟踪。用户暂停或接管手测时保留证据，等待新的指令。
- 优先复用已存在的生产逻辑。只修改确认受影响的路径。权限、输入和持久化校验跟随真实契约，避免臆造兜底、双轨实现、自动重试或没有消费者的接口。
- 用户的存档、编辑内容和未提交改动需要保全。可能改写状态的验证用获准的隔离实例或副本。删除、替换和迁移沿真实消费者检查影响，并按已确认的保留策略处理历史数据。

## 按变化选择技能

| 变化 | 读取 |
| --- | --- |
| 选择验证深度、解释证据或收尾清理 | `mc-verify-change` |
| 注册/定义增删、数据包、脚本优先级、存档、协议或发布 | `mc-data-evolution` |
| 权限、会话、交易、网络权威、维度或生命周期 | `mc-server-state` |
| GUI/HUD、模板、焦点、布局、槽位、弹层或相机输入 | `mc-ui-runtime` |
| 维护分支传播、加载器迁移、兼容注册或集成打包 | `mc-port-and-integration` |
| 图标、模型、结构、动画、图集或渲染差异 | `mc-assets` |

按需阅读本次涉及的技能及经验条目。有跨域风险时可请当前环境中实际可用的独立审查者核对，提供具体文件、风险和证据。实现与验收仍由任务执行者对照真实入口完成。

## 交接

- 列出修改边界、实际命令与操作、证据位置、已通过和未完成的检查。中断或交接时保留当前基线、决定、已完成步骤及具体阻塞。
