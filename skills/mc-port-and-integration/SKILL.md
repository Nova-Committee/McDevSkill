# 跨版本迁移与真实集成

先读 `mc-discipline`。

## 各维护分支分别核对

- 确认维护范围和远端基线，按分支逐一追踪缺陷的实际入口、依赖版本、资源、存档、协议与运行时。报告所在分支只是复现起点。分别标记受影响、已有修复、只经源码核对和不适用的分支。
- 每支用独立工作树、该版真实 API 和等价验收条件实现。对每支候选分别构建并运行受影响路径，证据与加载器、依赖、提交和产物哈希对应。跨版本做法必须从当前调用者重新确认。

## 第三方共存与注册所有权

- 找出两个模组是否在同一初始化阶段注册重复控件、钩子、菜单或插件。确认上游能完整承担预期行为后，按实际依赖是否存在，在对应平台的加载入口让本方整组互斥注册让位。控件层隐藏只能改变画面，无法消除事件或重复注册。
- 检查有依赖和无依赖两种路径。双方同装时使用真实客户端，核对唯一入口、点击、焦点、分页或实际业务动作；单装复测本方入口仍可用。

## 侧别、打包和真实依赖

- 物理客户端与逻辑服务端分别处理。公共消息、编码和专服加载路径隔离客户端类，显示由目标加载器支持的客户端桥接执行。
- 对比开发类路径与实际发行 JAR、嵌套依赖和资源源集。查当前实际加载件与依赖支持范围，按现有规则设置工具链和缓存。冷缓存或上游下载失败保留日志并先排查环境。
- 注册、配方、脚本和物品浏览插件以真实消费者发现与执行为证。上游已承担行为时清理重复实现。只有测试结果或实机现象说明范围需要扩大时，才补相关组合。
