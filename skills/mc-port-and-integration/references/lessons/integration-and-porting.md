# 跨分支移植与第三方共存

## 解决重复分页、页签和输入入口

- **适用条件** 当你发现两个模组单装都可用，同装后出现重复箭头、页签或事件时。
- **观察到的现象** 你可能看到界面多了一套按钮，隐藏其中一组以后，页签布局、命中或点击仍重复响应。
- **判断依据** 你要跟到双方实际注册的时点、依赖检测和输入处理，确认上游是否有能力完整负责这组行为。
- **做法** 你可以在加载入口按实际能力选择一个注册所有者，例如通过 `IMixinConfigPlugin` 一起停用本方互斥的布局与输入注入。用同装客户端操作剩下的箭头与页签，再单装确认本方入口恢复。
- **反例/坑** 你若只隐藏按钮或只关绘制注入，事件和页签定位可能仍由两方同时处理。仅有依赖存在也不足以证明其当前版本提供整组能力。

## 按分支移植同一个玩家可见契约

- **适用条件** 当你在一条维护分支收到缺陷，需要判断其他分支是否也受影响时。
- **观察到的现象** 你可能看到多个分支有相同功能，状态字段、协议入口或界面结构却各异，部分分支甚至没有同一个缺陷。
- **判断依据** 你要在各分支追到实际调用者、最终存储和加载器契约，以玩家可见行为与兼容范围判断等价性。
- **做法** 你可以用一张分支表记受影响入口与可复现条件。每支按自己的 API 实现，用对应产物和依赖复验。协议可选能力按两种连接方向分别核实。
- **反例/坑** 你若按同名方法直接搬补丁，可能改错状态范围或破坏旧档。一个分支的通过记录不能覆盖另一支。

## 能量和存储接口的表示边界

- **适用条件** 当你桥接大整数能量 API、存储事务或不同机型的容器附件时。
- **观察到的现象** 你可能看到高容量出现负值，显示数量与实际转移不同，或换一种机型后读写了错误的容器。
- **判断依据** 你需要查清两侧单位、数值范围、每次额度、容器索引，以及模拟和提交的含义。附件的类型、数量和顺序由实际机型与 API 决定。
- **做法** 你可以在从 `BigInteger` 转 `long` 前按接收端契约比较范围，分别约束可用量和请求额度。用零值、类型边界和超范围值验证模拟、真实事务及回读余额。
- **反例/坑** 你若用截断后的负数做钳制，转移量可能已经错误。显示有库存也不足以证明当前事务能提取。

## 让发行包的消费者实际发现联动

- **适用条件** 当你接入配方查看器、生物扩展事件或可选的运行时依赖时。
- **观察到的现象** 你可能看到开发环境发现了插件或事件，成品包却没有相同回调，或专服初始化时加载了客户端类。
- **判断依据** 你要查当前版本的发现机制、实际打包资源、物理侧、逻辑侧和事件总线。实体扩展若区分类型和形态，应按完整身份匹配。
- **做法** 你可以核对成品的注册和发现入口，用目标依赖分别看专服启动及客户端消费；发现机制已覆盖时保留单个入口。
- **反例/坑** 你若根据开发类路径额外补一份注册，生产环境可能调用两次。显示名相同也不能代表实体的逻辑身份一致。
